# PDFNova SEO audit and implementation — 9 November 2026

Baseline supplied by the owner: 121 clicks / 11,900 impressions over 28 days (1.02% CTR). The 3% target would represent approximately 357 clicks at unchanged impressions, position and query mix. This is a target, not a forecast. No Search Console query data or account access was available. No indexing request, sitemap submission or deployment was performed.

## Audit findings before changes

The repository uses Next.js 15 App Router, React 19 and TypeScript. SEO is already centralized in `src/seo/config.ts`, `landing/toolSeo.ts`, metadata builders and schema builders. The 34 indexable pages comprise nine static information/directory pages, 13 working tools and 12 statically generated blog posts. Blog slugs are generated from `src/blog/posts.ts`; unknown slugs use Next's 404 handling. There are seven additional public noindex pages (login, signup, password recovery, files, and three unfinished converters), a dynamic password-reset page, and an authentication callback handler. Manifest, icons, robots, sitemap and social-image routes are supporting resources.

Findings and decisions:

| Area | Before implementation / decision |

## Implemented changes

- Updated homepage and six conversion titles to express merge/compression, image output, DOCX output or supported Office input intent.
- Rewrote descriptions for JPG to PDF, PDF to Word and Word to PDF, preserving accurate server-assisted processing disclosure.
- Removed repetitive shared paragraphs while retaining distinct tool limitations, FAQs and instructions.
- Corrected merge result-upload copy and application schema permissions to disclose automatic signed-in archiving.
- Replaced broad processing/device badges with accurate processing models and modern-browser wording.
- Deferred both Google Analytics scripts with Next's `lazyOnload` strategy. This reduces competition during initial loading; it can miss very short visits. Vercel Analytics remains unchanged.
- Strengthened rendered SEO checks to compare actual Open Graph titles/descriptions and Twitter descriptions, require exactly one WebPage schema, and parse JSON-LD as raw script text (HTML entities are not decoded inside script data).

No PDF runner, API contract, authentication behavior, sitemap policy or redirect behavior changed. No new dependencies were introduced.

## Performance and remaining manual actions

No field LCP, INP or CLS measurements or PageSpeed/Lighthouse scores were available, so no numerical performance improvement is claimed. Existing swap font loading, reserved logo/artwork space, responsive layouts and on-demand PDF engines are retained. The production build reports approximately 130 kB first-load JS for home and 369 kB for tools. Follow up by profiling tool hydration and the options/preview dependency graph before attempting further bundle splitting. Keep the main tool immediately usable and reserve dimensions if deferring previews.

1. Review and deploy these repository changes through the normal release process. Run `npm run seo:check` after future metadata/route changes; it builds and performs the production SEO checks above.
2. In Search Console, select the `https://www.pdfnova.in/` property (or encompassing domain property). If unverified, use DNS domain verification or copy Google's HTML meta-tag token into the deployment's `GOOGLE_SITE_VERIFICATION` environment variable and redeploy. The local verifier found no token; a DNS-verified property needs no meta token.
3. Open **Indexing → Sitemaps**, enter `https://www.pdfnova.in/sitemap.xml`, and submit. Inspect its processing status and discovered pages. No submission was performed in this task.
4. After deployment, use **URL inspection → Test live URL** for home, PDF to Word, Word to PDF, JPG to PDF and the other changed converters. Confirm Google sees the canonical, rendered content and indexing eligibility; then request indexing where appropriate. Google chooses the final canonical and snippets.
5. Run Google's Rich Results Test on a tool and a blog post, and the Schema Markup Validator for full vocabulary validation. Do not add invented reviews to obtain eligibility.
6. Run PageSpeed Insights on home and representative mobile tool pages. Review Search Console **Core Web Vitals**, using field LCP ≤2.5s, INP ≤200ms and CLS ≤0.1 at the 75th percentile as follow-up targets. Measure before making further performance claims.
7. Export **Performance → Search results** with page, query, device, country, clicks, impressions, CTR and average position. Record the deployment date. After recrawling, compare equivalent 28-day windows and page/query cohorts; account for position and query-mix changes. Prioritize high-impression queries whose actual intent matches each tool. No query data was invented here.
8. Restore the backend's documented dependencies (including `ocrmypdf` and its system requirements) in its intended runtime and rerun API tests before a backend release.

The new snippets are expected to help qualified clicks by making outputs and supported formats easier to understand. CTR has not been shown to improve. Google must recrawl and may rewrite titles/descriptions; 3% is an objective, not a guaranteed result.
